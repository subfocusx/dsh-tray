# dsh-tray — назначение и связка запуска

> Этот файл описывает, **что** делает приложение и — главное — как две «ссылки»
> (обычный ярлык и Chrome App) стыкуются в единый рабочий сценарий.
> Обе ссылки одинаково важны: потеря одной из них ломает половину UX.

---

## Для чего это приложение

`dsh-tray` — это **трей-хост (watchdog) для DeepSeek Harness** (локальный сервер
`dsh web` на порту 3080), написанный на PowerShell + WinForms.

Оно решает одну задачу: **чтобы панель DeepSeek Harness жила всегда и открывалась
одним кликом**, без консоли, без ручного запуска и без «умер, надо перезапустить».

Что делает трей (вкратце):

- **Запускает сервер** (через `start-dsh.cmd`), если он ещё не слушает порт 3080.
- **Следит за здоровьем** сервера (HTTP-проба каждые N секунд).
- **Перезапускает упавший сервер** с растущей паузой (5s → 30s) и потолком
  попыток (`maxconsecutiverestarts`, по умолчанию 10) — после потолка требует
  ручного вмешательства («Рестарт dsh» в меню).
- **Показывает статус** в иконке трея (здоров/упал/нужно вмешательство),
  тосты о запуске/восстановлении/падении.
- **Следит за агентами** (`subagent.list`), даёт остановить работающего агента
  и открыть новую сессию — всё это с трей-меню, не блокируя интерфейс.
- **Проверяет обновления** пакета `@deepseek-ai/dsh`.

## ⚠️ ВАЖНО: запуск веб-панели (Web Publication) через Chrome App

**Ядро связки.** Веб-панель DeepSeek Harness открывается не «новой вкладкой в
браузере», а **отдельным окном установленного Chrome App (PWA)**. Это сознательное
решение: у панели своё окно, своя иконка в панели задач, свой профиль Chrome.

Ключ всей этой механики — одна строка в `dsh-tray.json`:

```json
"chromeapplnk": "C:\\Users\\<you>\\AppData\\Local\\Google\\Chrome\\User Data\\Profile 5\\Web Applications\\_crx_hgiemfgfjhalibdoboikeiepnnjapnpc\\DeepSeek Harness.lnk"
```

**⚠️ ЭТОТ ПУТЬ НЕЛЬЗЯ МЕНЯТЬ БЕЗ ЯВНОГО РАЗРЕШЕНИЯ ПОЛЬЗОВАТЕЛЯ.**
Он терялся при правках уже несколько раз — каждый раз это приводило к тихому
паду в обычную вкладку браузера. Верный путь ведёт на ярлык, чья цель:

```
chrome_proxy.exe --profile-directory="Profile 5" --app-id=hgiemfgfjhalibdoboikeiepnnjapnpc
```

См. поле `_chromeapplnk_donotchange` прямо над `chromeapplnk` в `dsh-tray.json`.

Как работает открытие панели (`Start-DshApp` в `dsh-tray.ps1`):

1. Если `chromeapplnk` задан **и** файл существует **и** его цель существует →
   `Start-Process` по ярлыку → открывается/активируется окно Chrome App.
2. Если хоть одно условие не выполнено → трей пишет в лог
   `WARN chromeapplnk ... PWA mode unavailable, falling back to a browser tab`
   и открывает `http://127.0.0.1:3080/` **вкладкой** — это и есть «тот самый»
   симптом, когда приложение «исчезает» и появляется вкладка.

> Открыть панель через Chrome App можно тремя способами: двойной клик по иконке
> трея, пункт меню «Открыть панель», и «Новая сессия» (она сначала пытается
> сделать новый диалог прямо в уже открытом окне приложения, и только при неудаче
> открывает панель).

## Вторая сторона: обычный ярлык (рабочий стол / меню «Пуск»)

Сервер поднимает **другая** ссылка — обычный ярлык Windows (на рабочем столе или
в меню «Пуск»), указывающий на `launch.cmd`.

**Он тоже должен быть корректным и вести на приложение.** Один двойной клик по нему:

1. Запускает трей-хост скрытно (`wscript dsh-tray-launch.vbs` → `dsh-tray.ps1`);
2. Ждёт, пока порт 3080 начнёт отвечать (`netstat … LISTENING`);
3. Открывает панель в окне Chrome App — но здесь `launch.cmd` всё ещё смотрит на
   **старый** путь `%APPDATA%\…\Start Menu\Programs\Chrome Apps\DeepSeek Harness.lnk`,
   которого на этой машине нет, и поэтому тоже молча падает во вкладку.

> ⚠️ Известная нестыковка: `launch.cmd` не обновлён на путь из профиля 5
> (реальный PWA живёт в `…\User Data\Profile 5\Web Applications\…`).
> Трей-меню открывает Chrome App корректно, а шаг 3 в `launch.cmd` — ещё нет.
> Нужно привести его к тому же пути, что и `chromeapplnk`.

## Связка: как две ссылки работают вместе

```
          ОБЫЧНЫЙ ЯРЛЫК (рабочий стол / Пуск)          ТРЕЙ-МЕНЮ / ДВОЙНОЙ КЛИК
          ───────────────────────────────────────      ─────────────────────────
                     launch.cmd                                иконка в трее
                          │                                        │
                          ▼                                        │
                 трей-хост (dsh-tray.ps1) ◄────────────────────────┘
                          │
          ┌───────────────┴───────────────┐
          ▼                               ▼
   сервер dsh web (порт 3080)      окно Chrome App (PWA)
   «голый» процесс без UI          → chrome_proxy.exe
                                    --profile-directory="Profile 5"
                                    --app-id=hgiemfgfjhalibdoboikeiepnnjapnpc
```

Получается: **приложение стыкует две вещи.**

1. **Через обычный ярлык** мы запускаем *сервер* (трей + `start-dsh.cmd`,
   watchdog с перезапусками) — это «машинария», она живёт в фоне.
2. **Через трей-меню** мы попадаем в *Chrome App* — отдельное окно панели,
   «лицо» продукта, куда пользователь кликает.

Одна половина без другой бессмысленна: без сервера Chrome App нечего показывать
(он открывает 127.0.0.1:3080), а без Chrome App сервер есть, но открывается
лишь неудобная вкладка вместо отдельного окна приложения.

**Итог:** обе ссылки — и `chromeapplnk` в конфиге, и ярлык запуска на рабочем
столе/в «Пуске» — это часть одной цепочки. Если после правок «приложение
открывается вкладкой, а не окном» — в 99% случаев потерялась/съехала первая.
Проверять в таком порядке:

1. `chromeapplnk` в `dsh-tray.json` указывает на существующий ярлык PWA;
2. цель этого ярлыка — `chrome_proxy.exe` с `--profile-directory="Profile 5" --app-id=hgiemfgfjhalibdoboikeiepnnjapnpc`;
3. `launch.cmd` использует тот же путь;
4. ярлык на рабочем столе/в «Пуске» ведёт на `launch.cmd`.

## Что наблюдал я (реальная картина на этой машине)

- PWA **уже установлен** и живёт в профиле 5 Chrome:
  `…\User Data\Profile 5\Web Applications\_crx_hgiemfgfjhalibdoboikeiepnnjapnpc\`
  (там лежат `DeepSeek Harness.lnk` и `DeepSeek Harness.ico`).
- В папке `Start Menu\…\Chrome Apps\` ярлыка `DeepSeek Harness.lnk` **нет** —
  там только `DeepSeek Harness Web.lnk` (и тот ведёт не на PWA, а на
  `dsh-tray-launch.vbs`) и `YouTube Music.lnk`.
- Поэтому старый конфиг честно писал в лог: `WARN chromeapplnk file not found:
  …Start Menu\…\Chrome Apps\DeepSeek Harness.lnk; …falling back to a browser tab`,
  и панель открывалась вкладкой.
- После перенаправления `chromeapplnk` на реальный ярлык из профиля 5
  (`chrome_proxy.exe --profile-directory="Profile 5" --app-id=…`) трей снова
  открывает Chrome App отдельным окном.

## Файлы, в которых живут «две ссылки»

| Файл | Роль |
|---|---|
| `dsh-tray.json` | конфиг; `chromeapplnk` = путь к Chrome App PWA |
| `dsh-tray.ps1` | трей: `Start-DshApp` решает Chrome App vs вкладка |
| `launch.cmd` | цель обычного ярлыка: запуск трея + ожидание :3080 + открытие PWA |
| `dsh-tray-launch.vbs` | скрытый запуск `dsh-tray.ps1` без консоли |
| `start-dsh.cmd` | поднимает сам сервер `dsh web` (порт 3080) |
