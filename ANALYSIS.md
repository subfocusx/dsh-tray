Дата анализа: 2026-08-19
Статус: **реализовано v1.7.1** (раздел 8 — v1.4.0, раздел 9 — v1.4.1, раздел 10 — v1.7.0, раздел 11 — v1.7.1: краш-луп backoff + потолок рестартов, async «новый диалог»/«stop агента», валидация числовых полей конфига)

## 1. Что это такое

`dsh-tray` — Windows-нативный трей-контроллер + watchdog для **DeepSeek Harness (`dsh web`)**.
Это **не плагин в смысле "bundle dsh"**, а самостоятельная программа: чистый PowerShell 5.1 + WinForms,
живущая в системном трее и управляющая жизненным циклом процесса `dsh web` (порт 3080).

Версия: **v1.3.0** (MIT, автор spacecat398 — отдельный репозиторий, сюда склонирован).

### Архитектура запуска

```
Автозагрузка (dsh-tray.lnk, Startup folder)
  -> wscript dsh-tray-launch.vbs            (безоконный лаунчер)
    -> powershell -WindowStyle Hidden -File dsh-tray.ps1   (WinForms-трей, watchdog)
      -> Start-Process cmd.exe /c start-dsh.cmd <port>     (стартует dsh)
        -> dsh web --port 3080
```

Ключевые файлы:

| Файл | Назначение |
|---|---|
| `dsh-tray.ps1` | Главный скрипт: WinForms-трей, меню, watchdog, health-check, i18n, конфиг |
| `dsh-tray-launch.vbs` | Безоконный лаунчер (двойной клик / автозапуск) |
| `dsh-tray.json` / `dsh-tray.example.json` | Локальный конфиг (пути, порт, флаги) |
| `start-dsh.cmd` | Шаблон запуска `dsh web` (получает порт как %1) |
| `install-autostart.ps1` | Отдельный скрипт установки/снятия автозапуска |
| `launch.cmd` | Ярлык рабочего стола: tray + ожидание порта + открытие PWA в Chrome |
| `setup-portproxy.ps1` | Легаси: netsh порт-проброс Win->WSL (не используется в текущем конфиге) |
| `assets\dsh-whale.png` | Иконка трея (белый кит, 64x64 PNG) |
| `_activate.mjs`, `_wintest.ps1` | Вспомогательные/диагностические скрипты (не документированы) |

## 4. Точки улучшения (что можно добавить/изменить)

### A. Автозапуск (самое очевидное, есть «на складе»)
Механизм полностью готов — включить = создать ярлык в Startup. Можно:
- просто проставить галочку в меню трея «Start with Windows», либо
- `powershell -File install-autostart.ps1`.

**Плюс как надёжность**: добавить дублирующую запись в реестр `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`
(переживает случайное удаление ярлыка; единая точка для всех автозапусков).

### B. Иконка «DipSika» / визуал
Сейчас — стандартный белый кит DeepSeek (64x64). Варианты:
- **Кастомная иконка**: заменить `assets\dsh-whale.png` своей картинкой (PNG/ICO). Файл легко подменить.
- **Набор иконок по состояниям** (Healthy/Starting/Error) вместо одного PNG + системных иконок — единый стиль.
- **Динамический бейдж** на иконке (например, число активных агентов), как делают в dsh-desktop.

### C. Монитор агентов в трее (по мотивам dsh-desktop)
Добавить пункт меню **«Агенты»**: список запущенных агентов, хвост лога каждого, кнопка **Stop**,
бейдж на иконке при завершении агента. dsh-desktop это даёт из коробки (живой монитор агентов).

### D. Нативные уведомления о событиях агента
Баллун на завершении/ошибке/вопросе агента — сейчас трей уведомляет только о состоянии **самого dsh web**,
не о событиях внутри сессий.

### E. Порядок/гигиена кода
- Легаси-файлы `setup-portproxy.ps1` (WSL-проброс) и `_activate.mjs`/`_wintest.ps1` в активном Windows-конфиге
  не нужны — можно перенести в `docs/` или удалить, чтобы не путали.
- В `launch.cmd` захардкожен **конкретный `chrome_proxy.exe` + `--app-id` PWA** — если пользователь не
  пользуется этим Chrome-профилем, меню «Открыть панель» (через `Start-Process $DashboardUrl`)
  — основной путь, и он надёжен; `launch.cmd` можно актуализировать под браузер по умолчанию.
- **i18n только zh/en**: при русской системе язык меню будет английский. Можно добавить `ru`.

### F. Дополнительные фичи-«хотелки»
| Идея | Польза |
|---|---|
| Быстрый «Открыть в браузере по умолчанию» | Надёжнее, чем захардкоженный Chrome PWA |
| Кнопка «Открыть папку логов/DATA» | Удобная навигация |
| «Скопировать URL 127.0.0.1:3080» в буфер | Быстрая вставка ссылки в браузер/коллеге |
| Дата/время аптайма dsh в строке статуса | Видно, сколько работает |
| Автообновление dsh (`npm i -g @deepseek-ai/dsh`) по кнопке | Один клик до новой версии (с подтверждением) |
| Автосворачивание окна при закрытии | Не путается с убийством сервера |

## 7. Важно при правках (правила dsh-tray)

- `dsh-tray.ps1` содержит кириллицу (если добавим `ru`) — файл обязан остаться **UTF-8 с BOM**, иначе
  PowerShell 5.1 декодирует как ANSI и получится синтаксический крах.
- Не добавлять **Exit** в меню — это осознанный дизайн (трей живёт вечно; остановка = меню Stop + kill трея).
- Стоп всегда через проверку identity процесса; не обходить её.
- Не менять порт без явной просьбы (оба URL выводятся из `port`).
- Трей — обычный пользовательский процесс, не служба и не от администратора.
- После правки скрипта трей перезапускается: убить старый процесс трея → `dsh-tray-launch.vbs`.
- `dsh-tray.json` содержит локальные пути — он в `.gitignore`, не коммитить.

## 8. Реализация v1.4.0 (внедрено 2026-08-19)

По запросу пользователя внедрены три блока:

### 🕵️ Монитор агентов в трее
- Пункт меню **«Агенты»** (раскрывающийся, с живым заголовком «Агентов запущено: N (ждут: M)»).
- Реально работает через `session.list` RPC: среди сессий отбираются `origin=='subagent'`;
  `running=true` → «работает», `continuable` + неактивен → «ждёт ввода».
- По каждому агенту — подменю **«Показать лог»** (окно с последним выводом из `subagent.history`:
  assistant-текст + причины `turn/end`) и **«Остановить агента»** (`subagent.interrupt`,
  для one-shot — `session.cancel`).
- Пункт **«Обновить»** — принудительное обновление списка.
- Отдельный таймер-полл (по умолчанию 5 с, `agentpollseconds`).

### 🔔 Нативные уведомления о событиях агента
- Дифф состояний между поллами: **запуск** (running → с новой сессией),
  **ожидание ввода** (running → waiting), **завершение/остановка** (исчез из отчёта).
- Первый полл — только «базовая линия», без ложных уведомлений о уже запущенных агентах.
- Переключается `agentnotifications` (по умолчанию вкл).

### 🔢 Иконка «DipSika» / визуал
- **Динамический бейдж**: при Healthy на иконке-ките (в прозрачном панданте к «DipSika»)
  в правом верхнем углу рисуется красный кружок с числом **запущенных** агентов (число кэшируется,
  чтобы не рисовать каждый тик). Ошибка/стоп по-прежнему показывают системные иконки.
- Свою картинку можно подставить просто заменив `assets\dsh-whale.png` (PNG 32–64px) — код подхватит её.
- Три языка: добавлена **русская** локализация (система `ru` теперь получает русское меню).

### Новые ключи конфига (`dsh-tray.json`)
`agentmonitor`, `agentpollseconds`, `agentnotifications`, `badgeicon`, `maxagentloglines`, `agenthistorylines`.
Все имеют безопасные значения по умолчанию; бэк-совместимы (старый конфиг без них работает).

### Файлы, которые изменены
- `dsh-tray.ps1` — v1.4.0 (BOM сохранён, парсинг 0 ошибок)
- `dsh-tray.json`, `dsh-tray.example.json` — новые ключи
- `README.md` — документация v1.4.0, таблица конфига, English, версии
- `ANALYSIS.md` — настоящий отчёт
- `backup-v1.3.0/dsh-tray.ps1` — резервная копия оригинала

### Как перезапустить трей (чтобы подхватить новую версию)
1. Правый клик по иконке → «Остановить dsh» (или просто оставить работать).
2. Убить старый процесс трея: `powershell -Command "Get-Process powershell | Where-Object {$_.MainWindowTitle -eq 'dsh-tray' }"` — проще: найти PID по мутексу нельзя, поэтому:
   `wmic process where "commandline like '%dsh-tray.ps1%'" get processid` → `taskkill /PID <pid> /F`.
3. Запустить заново: `wscript //nologo dsh-tray-launch.vbs`.
4. В логе `logs\dsh-tray.log` появится строка `... v1.4.0 ... Agent monitor enabled: poll=5s ...`.

> ⚠️ Заметка: `dsh web` (порт 3080) при этом остаётся живым — трей только перезапускается.

### Ограничения/честные оговорки
- «Ждёт ввода» определяется как неактивный, но `continuable` субагент — надёжный маркер «паузы на вопрос»
  отсутствует в RPC-поверхности, поэтому это best-effort (не вводит в заблуждение: помечается только явно
  continuable-пауза).
- Иконки бейджа кэшируются по числу и не освобождаются повторно — при живом конфиге это даёт несколько
  дескрипторов; для типичных 0–5 агентов приемлемо.
- Автозапуск с Windows **включён в меню, но НЕ активирован** (нужно поставить галочку или
  `powershell -File install-autostart.ps1`) — это отдельное системное изменение, сделано не молча.

## 9. Реализация v1.4.1 (внедрено 2026-08-19)

По запросу пользователя: «открывать **именно Chrome-приложение** (PWA), а не новую вкладку».

### Проблема
- «Открыть панель», двойной клик по иконке и «новый диалог» открывали `http://127.0.0.1:3080/`
  через `Start-Process` → обычная **вкладка** браузера.
- У пользователя есть рабочий ярлык `Chrome Apps\DeepSeek Harness.lnk`, который открывает
  установленное Chrome-приложение (PWA) отдельным окном. Проверка ярлыка показала: его цель —
  `chrome_proxy.exe --profile-directory="Profile 5" --app-id=hgiemfgfjhalibdoboikeiepnnjapnpc`
  (важно: **Profile 5**, а в `launch.cmd` был захардкожен **Profile 1** — не тот профиль!).

### Решение
- Новая функция **`Start-DshApp`**: если `chromeapplnk` задан и файл существует — запускает этот
  `.lnk` (открывает/активирует окно PWA), иначе — обычную вкладку браузера (fallback).
- На все точки открытия панели вызовы заменены на `Start-DshApp`:
  - пункт меню «Открыть панель»;
  - двойной клик по иконке;
  - «новый диалог» (после `session.create`) — открывает Chrome App (новая сессия появляется
    в списке слева внутри приложения);
  - fallback-ветки при ошибке `session.create`.
- Новый ключ конфига `chromeapplnk` (путь к `DeepSeek Harness.lnk`); дефолт `null` → совместимость
  со старыми конфигами, fallback на вкладку.
- `launch.cmd` исправлен: вместо жёсткого `Profile 1` + `--app-id` теперь открывает **тот же ярлык**
  пользователя (Profile 5), с fallback на `http://127.0.0.1:3080/`.

### Разводка пунктов «Открыть панель» vs «Новый диалог»
- **«Открыть панель»** (+ двойной клик по иконке) → `Start-DshApp`: активирует **то же окно Chrome App**.
- **«Новый диалог»** → сначала `Invoke-GuiNewConversation`: ищет уже открытое окно Chrome App
  (`Chrome_WidgetWin_1` + имя `DeepSeek Harness`) и кликает «新建会话/New conversation» прямо в нём —
  создание/выбор/localStorage делает сам GUI, т.е. **работа идёт именно в Chrome App**. Если окно Chrome App
  недоступно → fallback RPC `session.create` + `Start-DshApp` (новая сессия появится в списке слева внутри
  приложения).

### Кнопка «Exit» (добавлена в v1.4.1)
- Раньше «Стоп»/«Рестарт» только управляли сервером, а закрыть сам трей-процесс было нечем (приходилось
  вручную `taskkill`). По просьбе пользователя добавлен пункт **«Выход» (Exit)**.
- «Exit» останавливает dsh-сервер (`Stop-DshProxy`), выключает таймеры, прячет иконку, пишет в лог и
  вызывает `[System.Windows.Forms.Application]::Exit()` → message loop завершается, `Application::Run`
  возвращается, `finally` освобождает mutex, процесс трея завершается корректно.
- Языки: zh `退出`, en `Exit`, ru `Выход`.

### Файлы, которые изменены (v1.4.1)
- `dsh-tray.ps1` — v1.4.1: `Start-DshApp`, ключ `chromeapplnk`, замена всех открытий панели, пункт «Exit»
- `dsh-tray.json`, `dsh-tray.example.json` — `chromeapplnk`
- `launch.cmd` — открытие PWA через ярлык пользователя
- `README.md` — разделы про v1.4.1, конфиг, истории версий, English

## 11. Реализация v1.7.1 (внедрено 2026-08-19)

По запросу пользователя: «повысить стабильность», найдены и исправлены четыре конкретные проблемы.

### 🔄 Починен backoff при краш-петле (RestartCount сбрасывался после КАЖДОГО запуска)
- **Причина**: `Start-DshProxy` обнулял `$script:RestartCount` сразу после успешного `Start-Process`.
  Из-за этого backoff в `Invoke-HealthDecision` (`RestartDelaySeconds * min(RestartCount,6)`) никогда
  не рос: вечно падающий dsh перезапускался каждые ~5 с бесконечно.
- **Решение**: `RestartCount` обнуляется **только** в ветке `Invoke-HealthDecision -Healthy $true`
  (там же, где стоит `$script:HealthFailures = 0`), т.е. когда сервис реально подтверждён здоровым.
  `Start-DshProxy` больше не трогает счётчик. Backoff теперь реально эскалируется 5s→30s.
- **Потолок попыток**: новый конфиг-ключ `maxconsecutiverestarts` (дефолт **10**, безопасный,
  обратно совместим — старые `dsh-tray.json` без него работают). Когда счётчик достигает потолка,
  единая точка `Invoke-RestartCapHit`:
  - выключает автоперезапуск (`AutoRestartEnabled = $false`, снимает `RestartAfter`);
  - ставит статус **«Требуется вмешательство»** (новая строка локализации zh/en/ru) вместо «Stopped»;
  - показывает **один финальный** error-toast («dsh упал N раз подряд; автозапуск остановлен»);
  - логирует причину и текущие `HealthFailures` / `RestartCount` (`ERROR restart cap exceeded: ...`).
  Никаких повторных хаммеров процесса (guard `AutoRestartEnabled` в `Start-DshProxy`/`Invoke-HealthDecision`).
- **Ручной «Рестарт dsh»** (`Restart-DshProxy`) сбрасывает `RestartCapHit`/`RestartCount` и снова
  включает `AutoRestartEnabled` — один клик возобновляет цикл.

### ⚡ «Новый диалог» и «Остановить агента» больше не блокируют UI
- **Проблема**: `Invoke-GuiNewConversation` крутил до 20×`Start-Sleep 400 мс` (до ~8 с) прямо в клике
  «Новая сессия»; фолбэк `Start-NewConversation` дергал `Invoke-RestMethod -TimeoutSec 10` синхронно;
  `Stop-RunningAgent` звал `Invoke-DshRpc` синхронно из меню агентов.
- **Решение**: все три пути переведены на существующую инфраструктуру `Start-AsyncJob` /
  `Invoke-AsyncJobSweep` / `Invoke-AsyncJobCompleted` (тот же паттерн, что у healthprobe/agentpoll/updatecheck):
  - `Start-NewConversation` — неблокирующий kick задачи **`newconv`** на STA-runspace (UI Automation
    требует STA): `Start-AsyncJob -Id newconv -Apartment STA`. GUI-драйв + RPC-фолбэк выполняются
    в фоне; результат применяет `Complete-NewConversation` на UI-потоке в следующем тике (баллун /
    открытие панели с фрагментом). Пункт меню «Новая сессия» на время выполнения — disabled + «…».
  - `Stop-RunningAgent` — неблокирующий kick задачи **`agentstop-<sessionId>`** (per-agent id,
    двойной клик по тому же агенту не даёт второй задачи). Успех/ошибку показывает
    `Complete-AgentStop` (баллун «остановлен»/«interrupt failed» + force-poll).
  - `Invoke-AsyncJobCompleted` научился диспатчить `newconv` и `agentstop-*`.
  - Итоговое поведение (что видит пользователь) не изменилось — только блокировка убрана;
    в `Start-AsyncJob` добавлен опциональный `-Apartment` (дефолт прежний).
  - Бонус: `New-UpdateCheckScript` собирал функции без обёртки `function name {…}` — в runspace это
    превращалось в top-level код и проверка обновлений молча возвращала пусто. Обёртка добавлена
    (та же логика, что и для `newconv`).

## 12. Реализация v1.9.0 (внедрено 2026-08-20)

### Проблема
Тосты накладывались друг на друга (один модель на весь трей — новый заменял старый),
прозрачность отсутствовала, дизайн был слабый, анимация линейная/«дёрганая», а у
пользователя не было возможности посмотреть пропущенные уведомления.

### Решение
- **Стек тостов** ($script:Toasts, index 0 = самый новый): каждый тост получает свой
  вертикальный слот в правом верхнем углу (New-ToastSlotLayout), поэтому никогда не
  перекрывается. Лимит одновременных тостов — toastmax (по умолчанию 4, диапазон 1–8):
  при переполнении самый старый принудительно закрывается (Select-ToastStackTrim + Dismiss-Toast).
- **Вход анимацией**: slide-вход справа + fade (18 шагов, ease-out cubic); старые тосты
  плавно сдвигаются вниз (Start-ToastShift, 12 шагов); выход — fade + лёгкий подъём
  (Close-Toast, 10 шагов). Все таймеры жизненного цикла держатся в $script:ToastTimers
  (фикс v1.8.0 сохранён).
- **Debounce**: быстрый одинаковый тип события обновляет верхний тост на месте
  (Test-ToastShouldUpdateInPlace + Update-ToastInPlace) — стартовое «мигание» убрано;
  в отличие от v1.8.0, обновление работает и пока тост ещё входит (это и есть стартовый случай).
- **Тип-иконки + действие**: круглый MDL2-значок по типу (инфо/предупреждение/ошибка),
  акцентная полоса слева, кнопка действия (Открыть панель / Перезапустить dsh / Обновить,

- **История уведомлений**: новый пункт меню «Уведомления / Notifications / Уведомления»
  (Rebuild-NotificationMenu + Add-NotificationRecord, кап toasthistory, дедуп 30 с),
  клик по записи открывает панель, есть кнопка «Очистить».
- **Прозрачность**: toasttranslucent — лёгкая Mica-полупрозрачность на Win11 с
  автоматическим откатом к непрозрачности (фолбэк), если DWM не поддерживает.
- **Sweep** переписан под стек: перебирает @(), закрывает просроченные
